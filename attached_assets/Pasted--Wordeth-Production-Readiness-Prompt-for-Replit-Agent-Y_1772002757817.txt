### 1.2 — Tighten CORS to Specific Origins

**File:** `server.js`

**Problem:** `app.use(cors({ origin: true, credentials: true }))` allows any website to make credentialed cross-origin requests to your API. This is a CSRF vector.

**Fix:**
```js
const allowedOrigins = [
    'https://wordeth.com',
    'https://www.wordeth.com',
    process.env.CLIENT_URL,
    process.env.CORS_ORIGIN
].filter(Boolean);

app.use(cors({
    origin: (origin, callback) => {
        // Allow requests with no origin (mobile apps, curl, server-to-server)
        if (!origin) return callback(null, true);
        if (allowedOrigins.includes(origin) || process.env.NODE_ENV === 'development') {
            return callback(null, true);
        }
        return callback(new Error('Not allowed by CORS'));
    },
    credentials: true
}));
```

**Test:**
- In development, all origins should work (NODE_ENV=development).
- Verify that the `CLIENT_URL` env var is set to the correct domain in `.env`.

### 1.6 — Fix XSS in innerHTML Throughout Frontend

**Files:** `js/tournament-admin.js`, `js/partner-dashboard.js`, and any other frontend file using `.innerHTML` with data from the API.

**Problem:** Season names, artist names, city names from the database are injected directly into `.innerHTML`. An admin creating a season named `<script>alert(1)</script>` executes that script in the admin panel.

```js
function escapeHtml(str) {

```

Then replace every instance of direct injection like:
```js

```
with:
```js
element.innerHTML = `<div>${escapeHtml(data.seasonName)}</div>`
```

Audit **every `.innerHTML` assignment** in `tournament-admin.js` and `partner-dashboard.js` for all user-supplied strings including: season name, round name, artist name, submission title, city, country, company name, ad title.

### 1.7 — Fix RegEx Injection (ReDoS Vulnerability)

**Files:** `routes/auth.js`, `routes/creator.js`, `routes/user.js`

**Problem:** Name uniqueness checks build MongoDB regex queries by directly inserting user input:
```js
User.findOne({ name: { $regex: new RegExp(`^${name.trim()}$`, 'i') } })
```
A user registering with `name = '(.*)+@(.*)+@(.*)+@(.*)'` can cause catastrophic backtracking.

**Fix:** Escape the name before inserting it into the regex. Add this helper:
```js
function escapeRegex(str) {
    return str.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}
```
Then use it in all four locations where this pattern appears:
```js
User.findOne({ name: { $regex: new RegExp(`^${escapeRegex(name.trim())}$`, 'i') } })
```

Locations to fix:
- `routes/auth.js` — signup
- `routes/creator.js` — creator register
- `routes/user.js` — `/check-name` and `/profile` PUT

**Test:**
- Attempt to register with a name containing regex special characters like `(test.*)+`. It should either work as a literal name match or fail gracefully, not hang.

Calling `requireRole('LABEL_ADMIN')` on a route will lock out a superadmin.

**Fix:** Make the ADMIN bypass unconditional:
```js
module.exports.requireRole = function(...roles) {
    return (req, res, next) => {
        if (!req.user) return res.status(401).json({ message: 'Unauthorized' });
        if (req.user.role === 'ADMIN') return next(); // Superadmin bypasses all role checks
        if (!roles.includes(req.user.role)) {
            return res.status(403).json({ message: 'Insufficient permissions' });
        }
        next();
    };
};
```

**Test:**
- A user with `role: 'ADMIN'` should be able to access any endpoint protected by `requireRole('LABEL_ADMIN')`, `requireRole('ARTIST')`, etc.
- A user with `role: 'ARTIST'` should NOT be able to access `requireRole('LABEL_ADMIN')`.

### 5.1 — Fix `getPublicProfile()` Leaking Sensitive User Data

**File:** `models/User.js`

**Problem:** `getPublicProfile()` returns the entire user object minus password. This means endpoints like `GET /api/auth/verify` (called on every page load) and `GET /api/user/profile` return `role`, `subscriptionId`, `entitlementOverrides`, `creatorProfile.revenueShare`, `labelId`, `termsVersion`, `searchHistory`, `customMerch`, `following`, `followers`, and the full `creatorProfile` object to the client.

**Fix — replace the current implementation with a whitelist approach:**
```js
UserSchema.methods.getPublicProfile = function() {
    return {
        _id: this._id,
        name: this.name,
        email: this.email, // Only for the user's own profile calls
        bio: this.bio || '',
        avatar: this.avatar || '',
        accountType: this.accountType || 'fan',
        role: this.role,
        createdAt: this.createdAt,
        creatorProfile: this.creatorProfile ? {
            displayName: this.creatorProfile.displayName,
            handle: this.creatorProfile.handle,
            genres: this.creatorProfile.genres,
            socialLinks: this.creatorProfile.socialLinks
            // Do NOT include: revenueShare, storageUsedBytes, totalEarnings
        } : null
    };
};
```

Then add a separate `getSensitiveProfile()` method for internal use (like the dashboard endpoint) that includes subscription info, entitlements, etc. Update `routes/subscriptions.js` and `routes/creator.js` dashboard endpoints to call `getSensitiveProfile()` instead.

**Test:**
- Log in and decode what `/api/auth/verify` returns.
- It should NOT contain `searchHistory`, `customMerch`, `revenueShare`, `entitlementOverrides`, or `following`/`followers` arrays.
- It SHOULD contain `name`, `email`, `bio`, `avatar`, `accountType`, `role`, `createdAt`.

### 6.4 — Fix deploy.sh npm audit --force

**File:** `scripts/deploy.sh`

**Problem:** `npm audit fix --force` can upgrade dependencies to breaking major versions silently, which has caused production outages industry-wide.

**Fix:**
```bash
# OLD
npm audit fix --force || echo "⚠️  Some vulnerabilities may remain"
# NEW
if ! npm audit fix; then
    echo -e "${YELLOW}⚠️  Some vulnerabilities require manual review. Run 'npm audit' for details.${NC}"
    echo -e "${YELLOW}   If vulnerabilities are acceptable, continue deployment manually.${NC}"
    # Don't exit — let operator decide
fi
```

Also harden the test step — tests failing should block deployment:
```bash
# OLD
npm test || echo "⚠️  Some tests failed - continuing anyway"
# NEW  
if ! npm test; then
    echo -e "${RED}❌ Tests failed. Aborting deployment.${NC}"
    echo "   Fix tests or use --skip-tests flag if this is intentional."
    exit 1
fi
```
